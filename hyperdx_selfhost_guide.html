Przewodnik Wdrożenia Self-Hosted HyperDX

Kompleksowy przepis krok po kroku dla projektu TERMINAL

Architektura i Serwery Projektu Infra Spec

W tym środowisku wyodrębnione są trzy warstwy sieciowe:

1. Serwer Nginx Reverse Proxy / Brzegowy (IP: 153.19.51.129):
Serwer wejściowy z internetu. To na nim definiuje się reguły Nginx i certyfikaty SSL/TLS dla subdomen telemetry.terminal.eti.pg.edu.pl oraz opcjonalnie hyperdx.terminal.eti.pg.edu.pl.

2. Dedykowany Serwer HyperDX (IP wewnętrzne: 172.20.3.153):
Dedykowana maszyna wirtualna przeznaczona na instalację HyperDX i ClickHouse.

3. Serwer Aplikacyjny / Docker Host (IP publiczne: 153.19.51.139 | IP wewnętrzne: 172.20.3.97):
Główny serwer, na którym działają kontenery Docker aplikacji (Backend, Frontend, Postgres).
1
Uruchomienie HyperDX na Dedykowanym Serwerze (172.20.3.153) Infra

Zaloguj się przez SSH na dedykowany serwer HyperDX (172.20.3.153), utwórz katalog dla HyperDX i uruchom kontener za pomocą Docker Compose.

# 1. Zaloguj się przez SSH na serwer HyperDX (172.20.3.153)
ssh uzytkownik@172.20.3.153

# 2. Utwórz katalog i pobierz repozytorium HyperDX
mkdir -p /opt/hyperdx && cd /opt/hyperdx
git clone https://github.com/hyperdxio/hyperdx.git .

# 3. Uruchom stos Docker w tle
cd docker
docker compose up -d
Co zostało uruchomione na serwerze 172.20.3.153?
• Port 4318: Kolektor OTLP HTTP (zbiera logi i metryki od Backendu i Frontendu).
• Port 8080: Web UI (Panel interfejsu graficznego, skąd pobierzesz swój lokalny API Key).
• Port 8123: Interfejs HTTP bazy ClickHouse (do zapytań SQL z konsoli).
2
Konfiguracja Nginx na Serwerze Brzegowym (153.19.51.129) Proxy

Na serwerze Reverse Proxy (153.19.51.129) dodaj wirtualny host, który przekaże ruch z internetu na dedykowany serwer HyperDX (172.20.3.153:4318).

/etc/nginx/sites-available/telemetry.conf (na serwerze 153.19.51.129)
server {
    listen 80;
    server_name telemetry.terminal.eti.pg.edu.pl;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name telemetry.terminal.eti.pg.edu.pl;

    ssl_certificate /etc/letsencrypt/live/telemetry.terminal.eti.pg.edu.pl/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/telemetry.terminal.eti.pg.edu.pl/privkey.pem;

    location / {
        # Przekierowanie do dedykowanego serwera HyperDX na port 4318 (OTLP HTTP Kolektor)
        proxy_pass http://172.20.3.153:4318;
        
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
3
Uruchomienie i Dostęp do Web GUI HyperDX (Port 8080) Interfejs GUI

Interfejs graficzny HyperDX (GUI) uruchamia się automatycznie na porcie 8080 serwera HyperDX (172.20.3.153). Masz dwie opcje uzyskania do niego dostępu:

Opcja A: Wystawienie GUI przez Nginx brzegowy na nowej domenie (hyperdx.terminal.eti.pg.edu.pl)

/etc/nginx/sites-available/hyperdx-gui.conf (na serwerze 153.19.51.129)
server {
    listen 443 ssl http2;
    server_name hyperdx.terminal.eti.pg.edu.pl;

    ssl_certificate /etc/letsencrypt/live/hyperdx.terminal.eti.pg.edu.pl/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/hyperdx.terminal.eti.pg.edu.pl/privkey.pem;

    location / {
        # Przekierowanie do dedykowanego serwera HyperDX na port 8080 (HyperDX Web UI)
        proxy_pass http://172.20.3.153:8080;
        
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
    }
}

Opcja B: Bezpośrednie połączenie przez Tunel SSH (Zalecane — bez modyfikacji Nginx)

Możesz utworzyć tunel i otworzyć GUI lokalnie na swoim komputerze:

# Na swoim komputerze wpisz (przez bastion/serwer lub bezpośrednio na IP HyperDX):
ssh -L 8080:172.20.3.153:8080 uzytkownik@153.19.51.139

# Następnie otwórz w przeglądarce na swoim komputerze:
http://localhost:8080
Pierwsze logowanie do GUI & Ingestion API Key:
Po otwarciu panelu zarejestruj swoje konto administratora. W zakładce Team Settings skopiuj swój prywatny Ingestion API Key. Użyjesz go w:
1. Pliku .env serwera aplikacyjnego jako HYPERDX_API_KEY.
2. Nagłówku OpenTelemetry jako OTEL_EXPORTER_OTLP_HEADERS=Authorization=TWÓJ_KEY.
3. Sekretach GitHub Actions jako HDX_OTEL_EXPORTER_OTLP_HEADERS i HDX_API_KEY.

Modyfikacja Kodu Frontendu (React) Edycja Kodu

Skonfiguruj SDK @hyperdx/browser w pliku Client/src/main.tsx, przekazując parametr url wskazujący na adres Nginx kolektora.

Client/src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import HyperDX from "@hyperdx/browser";
import "./index.css";
import App from "./App.tsx";

HyperDX.init({
  apiKey: import.meta.env.VITE_HYPERDX_API_KEY,
  service: "terminal-frontend",
+   url: import.meta.env.VITE_HYPERDX_URL || "https://telemetry.terminal.eti.pg.edu.pl",
-   tracePropagationTargets: [/localhost/],
+   tracePropagationTargets: [/localhost/, /terminal\.eti\.pg\.edu\.pl/],
  consoleCapture: true,
});

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>
);

Modyfikacja Client/Dockerfile Edycja Kodu

Umożliw przekazanie adresu VITE_HYPERDX_URL podczas budowania kontenera klienta.

Client/Dockerfile
FROM node:alpine AS build
WORKDIR /src
+ ARG VITE_HYPERDX_API_KEY
+ ARG VITE_HYPERDX_URL
+ ENV VITE_HYPERDX_API_KEY=$VITE_HYPERDX_API_KEY
+ ENV VITE_HYPERDX_URL=$VITE_HYPERDX_URL
COPY package*.json .
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /src/dist /usr/share/nginx/html
COPY ./nginx.conf etc/nginx/conf.d/default.conf
EXPOSE 5173
CMD [ "nginx", "-g", "daemon off;"]

Alternatywa: Odpytywanie Metryk z Konsoli (CLI / Bez GUI) CLI Workflow

Oprócz Web GUI, w dowolnym momencie możesz wyciągać metryki bezpośrednio w konsoli SSH.

A. Wejście do konsoli SQL bazy ClickHouse:

docker exec -it hyperdx-clickhouse clickhouse-client

B. Zapytanie SQL o metryki wydajnościowe backendu:

-- Wyświetlenie średniego i maksymalnego czasu trwania zapytań HTTP
SELECT 
    metric_name, 
    avg(value) AS avg_duration_ms, 
    max(value) AS max_duration_ms,
    count() AS total_requests
FROM hyperdx.metrics 
WHERE metric_name = 'http.server.request.duration' 
GROUP BY metric_name;

C. Odpytanie o metryki jednym poleceniem cURL z terminala Linux:

curl -s 'http://127.0.0.1:8123/?query=SELECT+metric_name,value+FROM+hyperdx.metrics+ORDER+BY+timestamp+DESC+LIMIT+10'
